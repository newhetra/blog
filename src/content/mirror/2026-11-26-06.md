> 这五份速查我攒了三年，一直在本地改。这次整理成包，是因为上周同事又问我「429 和 5xx 同时出现先看哪个」——这种问题每次都搜一遍太亏了。

## 包里有五份清单

1. **正则速查**：校验类（邮箱/IP/手机号/日期）、提取类（URL/色值），以及三个最容易踩的坑
2. **Git 命令卡**：救火四条放最前面（restore / reset --soft / reflog），然后是日常和分支操作
3. **Shell 与 PowerShell 对照表**：grep/awk/sed 的等价写法，Windows 特有的端口占用和服务管理
4. **HTTP 状态码排查顺序**：401 和 403 的分界、404 的三层排查、500 的标准顺序
5. **AI 提示词模板**：报错定位、代码审查、写测试、重构——四个开发场景的骨架

## 三个我印象最深的例子

**正则的贪婪匹配**：提取 HTML 注释用 `<!--(.*?)-->`，写成 `<!--(.*)-->` 会从第一个注释头匹配到最后一个注释尾，一次贪心毁掉整个提取。

**找回消失的提交**：`reset --hard` 之后别慌，`git reflog` 里那条记录还在，`checkout` 回去就行——知道这一条，等于给手滑上了保险。

**429 和 5xx 混着出现**：先看限流再看下游。限流在前面挡着的时候，下游的错误日志全是噪声，顺序反了会排查一整晚。

## 为什么是 Markdown 而不是网页

速查类内容的核心诉求是「能搜、能复制命令」。Markdown 在任何编辑器里都能全局搜索，命令直接复制粘贴就能跑，不需要在网页里找复制按钮。
