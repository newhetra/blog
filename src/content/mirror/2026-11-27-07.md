> 结论先行：如果你每天在终端里看代码、看日志、看配置，`cat` 该退休了。`bat` 是它的现代替代——语法高亮、行号、Git 集成，一个命令全带走。Apache-2.0，6 万+ star。

## 它解决什么

看代码片段时的三个高频动作：看清楚结构（高亮）、知道在第几行（行号）、确认这段代码改没改过（Git 状态）。`cat` 一个都做不了，`bat` 全部原生自带，而且默认行为就是人类想要的——输出到终端自动分页，输出到管道自动变纯文本，不需要任何参数调整。

## 三条最有价值的能力

**语法高亮覆盖面**：基于 syntax-highlighting 引擎，支持两百多种语言，包括取证里常见的日志格式。配合 `--theme` 可以换主题，深色浅色终端都有合适的。

**Git 集成**：在 Git 仓库里 `bat main.py`，行号旁边直接显示每行的修改状态（新增/修改），review 自己的改动不用开 IDE。

**精确行号定位**：`bat src/main.rs --line-range 30:50` 直接看 30 到 50 行；`bat -r 40:` 从第 40 行看到结尾。配合搜索结果跳转比编辑器还快。

## 上手

Windows 有 winget/scoop 安装渠道，也有便携版 exe。装完在 PowerShell 里：

```
bat app.py              # 带高亮看整个文件
bat -A app.log          # 显示不可见字符（排查空白符问题神器）
bat config.yaml --theme=TwoDark
```

`-A`（show-all）显示 tab 和换行符，排查"看起来一样的两行为什么不一样"时是杀手锏。

## 一个容易被忽略的点

`bat` 在管道里会自动退化为纯文本输出：`bat file | grep xxx` 不会把 ANSI 颜色码带进 grep。想强制保留颜色用 `--force-colorization`，写自动化脚本时这个开关很有用。
